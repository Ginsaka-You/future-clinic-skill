# 候选关系、主路线与未来推演

本参考解释研究中的判断和报告中的主次，不是固定目录、字段表或路线数量规则。显式调用即开始；先复用已有且仍然有效的 Brief 与用户输入，再核对关键原始来源。

## 1. 先确定此刻真正需要解决什么

用自然语言恢复核心目标、当前已知、已有投入或候选、时间/事件边界与成功表现。目标可以是理解、核验或设计，不因没有现成选项退出。尤其分清探索新办法、验证已提出的办法、选择实施策略与实施本身；不能把上一轮宽泛目标自动带到用户已经收窄的这一轮。Brief 是索引而不是裁判：最新明确指令优先，旧材料中的推荐仍只是待审视的意见。

共享深度诊断底座把当前事实、未知与边界，纵向形成与演化，横向竞争解释，交叉位置的矛盾与驱动力接成同一因果解释。只保留会改变候选、阶段、推荐、失败条件或换路信号的背景。问题复杂时继续向下追因果，而不是因篇幅短就浅尝辄止；问题简单时不补一部历史。

能查的先查。不重复询问已经解决的问题；只有用户知道且不同回答会实质改变安全性、当前问题模型、第一步行动或主路线，又不能安全条件化时，才合并必要问题自然提问。深度研究中新发现这样的关键用户未知，也停止依赖它的结论，不生成最终报告；继续独立研究，用户回答后在同一已启动会诊内继续，无须重新调用 Skill。其余未知用假设、条件分支、范围或重选信号表达。

## 2. 保持事实强度与适用范围

区分已核验事实、用户观察/偏好、外部一般规律、模型假设及未知。一般研究不能证明这个用户、这个系统或这个现场的效果；来源冲突及其决策影响不得抹平。保留来源中的对象、数量、时间、逻辑条件和确定程度：未提及不等于不存在，稀少不等于零，当前截面不证明趋势，线索或评价责任不等于已标注样本。趋势需口径可比的基准，动机与历史不能为填框架而编造。

候选关系中的依赖也是事实主张。某一实现需要额外输入，不证明整个机制家族都必须等待该输入；概念探索、扩大工程、完整评价与现场启用也可能有不同前置。单次设置无改善，不直接否定尚未检验的实现、配置或机制。类别归并不自动意味着相同模型、联合实现或统一准入条件。同输入下仍可有不同判断函数。必要条件、排除及不可逆排序，须有相应范围的证据，否则保留竞争解释并设计区分观察。

原有评价范围、期限、责任与成功标准不因候选输出而改变。不确定、保守、不触发或暂缓，不是删除原对象或失败记录的理由；输入确实无效时按既有规则核证并保留原记录。多维取舍不能偷换成单项前进门槛。假设不能擅自收窄或扩张用户明确的可选范围；值得扩张的部分单列边界变化，不作为已获授权条件。

可控行动与未知结果分开。推演到某个时点时只使用届时可知信息，不能拿未来反馈支持当前推荐。研究期真值、部署后数据与单次运行可见信息不能相互顶替。相同护栏集中写；会反转选择的例外与反证贴近相关论点，不藏在附录，也不反复把每段写成免责声明。

## 3. 外部研究只为改变判断

默认做目标定向外部研究：某项答案改变哪个候选、关系、后果、失败条件、成本、参与者反应、参考类或换路信号？优先权威一手来源、反例与可比失败案例，必要时查询行为者怎样适应或信息怎样取得。时间敏感事实核验并注明截止点。若提供了冻结材料且任务要求只用它们，则尊重输入边界，不以重新联网悄悄改变对照条件。

连续新增资料不再改变上述判断时停止，不靠来源数量制造广度。起点有争议就先核查可核部分，未解决事项仍为未知，让路线处理它，不把争议当退出理由。正文来源可点击，说明来源实际支持的是哪项机制或限制；引用与链接本身不证明结论适用。

## 4. 候选先有关系，路线才有阶段

先展开较宽候选池，再问各候选在回答什么问题、位于什么时间尺度。完整推进策略、互斥替代、可同时采用的组件、共同能力、类别与具体实现、前后阶段、条件分支、外部结果，不应混成同一菜单。条件成立后才可实施的分支也可能现在就能核验前提；不可把部署门槛前移为所有研究的门槛。

所有真实且决策相关的候选必须可见。用户明确点名的办法，即使是某条路线的局部实现，也保留其具体做法、独有机制、差异与验证安排；“已归类”不等于已经回答。被支配、合并或暂缓的说明理由和重选条件，不删除独有反例。只有机制、责任、信息、承诺及后果没有实质差别时才合并重复描述。

从这些关系出发，安排候选怎样经过行动与反馈发展。阶段表达实质状态变化或待解决问题，不只是技术专题；先后依赖要有依据，允许并行、重叠、回返与条件激活。不为每个阶段重新列一组同名路径，也不把所有问题压进一条不可分叉时间线。同一候选跨阶段保持身份，交代它改变的能力、证据与限制。研究、现场生命周期或算法内部事件可嵌套，但交接的是具体成果，不互相顶替。

再比较少而不失真的整体推进策略。最小主路线集合的意思是去掉重复推演，不是预先限制选项数量。可以只有一个共同过程及内部真实分叉；也可以有多条不可压缩的竞争路线。共同平台不是与算法竞争的一个选项；技术问题也不必抬成管理战略。粒度应直接回答用户的问题。

候选广度与路线结构可以互相修正。新增候选还会改变机制、责任、承诺、后果或换路信号，就继续探索；穷举组件的所有排列组合通常没有决策价值。用户要验证多个候选时，推荐一套验证策略不意味着宣布唯一候选获胜。

## 5. 深度跟着取舍走，不跟着目录平均分

先公平比较有意义的备选，暂定推荐，再深入推演并允许推翻推荐。分析每条值得完整追踪的主路线时，从共同当前状态连接：采取什么行动或投入组合，首先观察什么，反馈改变何种能力、约束或解释，然后作什么具体选择，怎样走到稳定结果、失败形态或换路。

推荐路线是主要篇幅所在，必须讲清最大弱点、最强反例、不可逆成本、保留的选择权，以及继续、加码、收缩、切换或停止的可观察信号。参与者确有作用时分析其激励、负担和适应；没有依据就保留条件，不虚构反应。两跳只是最低检查点；若再向后一层仍会改变推荐、不可逆性或失败判断，就继续。不要以“继续优化”“全部深化”收束不同反馈。

最强竞争路线须深入到读者知道它在什么条件下更好、何时应改走它；不能故意挑弱对手衬托推荐。其他候选保留足以公平比较、验证与重选的信息。共同能力集中说明服务谁、何时用；局部实现和子分支只展开影响取舍的差别，不各复制一整套相同流程。已指定逐项验证的对象，无论是否主推，都要让读者找到待验证承诺、第一项有区分力的观察及结果后的处置。

分支成功、失败、暂不采用时，交代主过程怎样继续、哪些责任仍未解决。汇合不能清空各支成果、成本或限制。“停止这一实现”不代表原问题已消失。跨分支采用组件，说明它带来什么，不悄悄用合并名称替代机制比较。

## 6. 推荐、情景与预测

推荐当前较稳健、信息价值高、保留选择权且失败损失可控的第一步，而非永久赢家；解释为什么不是最强替代。多候选并用时说明组合、先后或条件结构及各自贡献。实质分歧直接展示，并提出能区分它的证据；不靠投票或静默综合。推演后发现反例击穿推荐，就改推荐而非隐藏反例。

深度不确定时用少量真正能挑战策略的情景，不只改写乐观/中性/悲观语气。情景是挑战，不是预测。比较哪些未来仍可接受、何时失败、是否及时可见、能否换路及代价。观察方式与责任有依据才具体化；阈值来自规则、数据或明确事件，不编精确数字、时间或人物。

只有命题可判定、参考类或数据可解释，并具备信息截止点、判定日期、客观规则与更新条件时才给概率。影响决策的预测及更新条件保留在 Markdown 内；单次命中不证明校准。条件不齐用条件推演，不给装饰百分比。用户已选定目标未来时才用 backcasting 倒推能力与不可逆节点；能倒推出路径不证明目标值得追求。文化或象征性解释明确不是科学预测，不虚构必然事件。

## 7. 报告从读者需要出发

分析时先比较再推荐，阅读时可以结论先行。开头用普通话说明当前建议、为何优于主要替代、第一反馈和改主意的条件，具体到读者知道要做什么。随后交代必要底座及候选关系，再沿主路线分阶段深入；最强替代在影响取舍的位置比较。标题按内容自然命名，这个阅读顺序不是每份报告必须照填的章节表。

保持稳定名称，让候选关系、主线阶段和推荐描述同一过程。细节扩充主论证，而不是每到一个阶段又重开新的路径菜单。共性集中写，关键例外就近写。若技术差别决定取舍，就留在正文，不为了“策略感”隐藏它；不影响当前判断的运行流水、版本哈希和审计记录才放附件。没有字数或页面指标，删重复不删责任。

给信息一个清楚的归属位置。开头只交代核心取舍与第一步，不预先复述每个候选的完整实验。候选关系说明“彼此是什么关系、差别为何影响选择”；主路线相应阶段再完整说明“具体怎样验证、结果怎样改变后续”。同一验证安排不再复制到末尾行动表、预测账本和风险清单里；若结尾需要提醒，用当前动作与下一决定收束，并定位已有正文。普通验证方案不因包含未来动作就另造预测账本。共享证据边界与评价规则集中表达，分支只补特有条件。背景数字和技术细节按对取舍的作用保留，不能因为已核对就全搬进正文。

完成初稿后从头连续读：新一节是否推进了判断，还是换名称复述前文？去掉重复仍应保留候选身份、机制差别、指定验证责任、决定性反证及反馈后的去向。可读性由这样的组织改善，不靠删难题、任意字数上限或另写一份更好懂的聊天来获得。

图是可选辅助，不是交付门槛；必须与文字同义，不能补造依赖、结果或假确定性。未经计算和核验的推演不叫仿真。

### 一个简短示意：已有展览讲义怎样改进

用户已有纸样，考虑图解、文字、两者结合，能做朗读检查，真实读者理解未知。图解与文字是解释方式，组合可能互补；朗读是共用检查，试读是获取理解反馈，不能当成四五条同级路线。

当前可推荐先对同一难点制作图解与文字小样并试读，而非立即重做全册。先比较单一表达，若分别暴露互补遗漏，再做针对性的组合；若只是术语或图例问题，先局部修复并复试。有效结果支持逐步扩展到其他难点；若改过后仍误解，返回概念取舍而不是堆更多形式。朗读可并行，不能代替真实理解证据。

最强替代是直接做组合稿：若已有读者证据确认两种表达缺一不可，它可能更省时间；但现阶段这种证据未给，直接重做增加无效工作和阅读负担。这解释了当前推荐，也说明何时反转。它不是每个任务都应采用“两小样再组合”的规则。

## 8. 同源交付与检查顺序

先确定 `report_title` 和 `artifact_stem`：用户明确指定报告名称时优先使用；未指定就按对象与研究目的命名，可附日期。移除 `/ : * ? " < > |`，不要默认使用 report/output。Markdown 与 PDF 使用完全相同的实际主名；已存在时追加 `_2`、`_3`，不得覆盖旧产物。Markdown 一级标题与 PDF 封面同为 `report_title`，署名 `游诗辰 · Future Clinic`，聊天链接引用实际名称。

Markdown 是唯一完整语义源，PDF 从最终 Markdown 直接渲染，聊天摘要不另增框架或结论。聊天先讲清同一推荐及其依据、候选关系与后续、最大风险及换路条件，再链接实际文件。可选轻量 manifest 只记录文件身份、时间与哈希，不承载独有语义，不代表接受或现实有效。

PDF 使用本 Skill 的独立渲染器，见 [pdf-rendering.md](pdf-rendering.md)。显式传入 `--author "游诗辰 · Future Clinic"`。提取文本核对标题、署名、推荐、关键机制、风险、后续及来源链接，再逐页查看中文、裁切、溢出、表格与空白页。修复后复查受影响重排范围；全局字体或样式改变则复查全部。尊重宿主提供的兼容环境，先诊断发现/链接问题，再按授权安装最小依赖，不以重启桌面应用解决依赖。不把丢表格和链接的纯文本打印视为合格 PDF。

检查先后是：任务是否承接正确；候选和关系是否完整准确；推荐相对最强替代是否成立；整个未来过程是否连贯可追踪；决定性事实与反例是否可靠；最后是表达和文件。只给检查者报告本体，也应能回答当前做什么、为什么、先看什么反馈、之后怎样继续及如何换路。没有阶段词不自动失败，有阶段词或逐阶段路径组也不自动通过。格式测试、来源数、哈希或图都不能证明研究质量。

## 9. 研究与现实行动的边界

研究默认不授权发送、购买、部署、业务修改或现场实施；有明确实施授权时按其范围行动，不能因研究方法扩权。关键事实不足可以先验证条件，不把未知当取消候选的理由。真实权限或环境障碍只阻断依赖部分，保留独立成果并说明缺口。不要建立跨任务状态机、历史 Case、Runtime、Hook 或固定 Agent 拓扑，不修改无关配置或其他产品，不退出、重启、重装或前台唤起 Codex／ChatGPT。
