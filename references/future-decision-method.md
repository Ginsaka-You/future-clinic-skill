# Future Clinic Shared Deep Base and Future Pathways

用户显式调用 `$future-clinic` 后立即读取本参考，不存在额外入口判定。它提供共享深度诊断底座、阶段／状态坐标、选择点内的候选比较、跨阶段轨迹与质量检查，不是固定字段 Schema。候选保持广度；阶段和轨迹由对象的真实发展关系决定，不由产品预设数量。

当前对话或用户给定路径存在 Future Brief 时，先读取它，复用其中已经确认且仍然有效的目标、用户输入、偏好、护栏和来源索引，不重复询问已经解决的问题。Future Brief 是目标与输入索引，不是外部事实的证明；会约束路线的关键原始来源仍需核对。没有 Future Brief 时仍无条件启动，并做一次快速就绪检查。

## 1. 核心目标与共享深度诊断底座

先构造一个自然语言目标框架，不做任务类型分类：

- **核心目标**：用户真正希望理解、核验、改变或完成什么。
- **当前状态**：与目标直接相关的事实、材料、已有动作、约束和未知。
- **时间或事件边界**：若任务存在窗口、不可逆节点或复议节点就写清；没有依据时不编日期。
- **成功与护栏**：什么结果算有用，以及绝不能牺牲什么。
- **路径依赖**：只恢复会改变当前路线的既有承诺、投入、失败、能力、关系或截止点。

能从上下文、文件或可靠来源查清的先查。只有某项信息仅用户知道，而且不同答案会改变安全性、当前问题模型、第一步行动或主路线时，才自然提问；问题数量服从同一个关键缺口的实际需要，不做固定问卷。若只是影响可逆细节，可以给明确假设、条件分支、范围收窄或换路信号，不必打断。缺少 Future Brief、现成决策者、选项或未来分歧不影响启动，也不得触发退出。

然后把与目标真正相关的上下文接成一段共享解释，让候选路线从同一个深底座分叉，而不是悬空生成：

- **当前截面**：当前事实、关键未知与授权／安全／时间边界分别是什么，哪些事实会直接约束路线。
- **纵向形成与演化**：局面如何形成，哪些选择、反馈、能力、关系或外部变化把它推到今天；只追踪会改变未来机制的历史，不默认写完整对象史。
- **横向竞争解释**：至少保留那些会导向不同路线的竞争解释，写清各自支持证据、反证和可区分信号，不把首个顺手解释当成事实。
- **交叉位置、矛盾与驱动力**：把当前局面放回形成过程与竞争解释的交叉点，指出真正卡住未来的关键矛盾，以及会放大、缓和或反转它的驱动力。

这四个视角是思考问题，不是必须逐栏填满的 Schema。简单任务的共享底座可以是数段文字；复杂、长期或高不确定任务必须继续向下追，直到新增背景不再改变路线机制、排序、阶段演化、失败形态或换路信号。不得因为先讲底座就默认串联完整横纵研究；Future Clinic 只保留足以解释未来分叉的纵横深度。

## 2. 证据分层

在分析过程中保持以下标签的语义边界，正文可用自然语言表达：

| 层级 | 含义 | 可承担的作用 |
|---|---|---|
| 已验证事实 | 本轮从原始记录、权威来源或可复查数据核验 | 可直接约束路线 |
| 用户输入 | 用户当前明确提供的目标、观察、资源或偏好 | 作为该决策的输入，但不自动外推 |
| 外部一般规律 | 研究、规则、参考类或相似案例 | 提供机制或基准率，不能冒充个人事实 |
| 模型假设 | 为连接因果链暂时采用的解释 | 必须显示成立条件与击穿证据 |
| 未知 | 目前不能可靠判断且可能改变选择的变量 | 驱动信息购买、情景或换路信号 |

来源冲突时保留冲突及其决策影响。来源没有解决的事项继续标为未知，不以多数网页代替真相。保留输入原有的范围、数量、时间、逻辑条件和确定程度：没有提到不等于没有，稀少不等于为零，待核线索或评价责任不等于已标注样本，当前收支不证明可投入资源的上限。原有多维取舍不压成单项指标的前进门槛；任一或全部、首次或重复等条件强度及触发后的责任须原义保留。当前截面或近期片段不直接证明增减趋势，趋势比较需要有据且口径可比的基准。只恢复有依据的历史，不为补齐框架推断用户动机、既往维护或功能使用情况。

区分行动／算法的输出状态、证据完整性与对象的评价资格。输出保守或不确定，不自动改变原对象的评价资格、分母、期限和成功标准，也不能把原本应计的失败移出评价。若原始输入确实无效，按既有规则核证其影响并保留原记录；不能从策略输出倒推放宽原评价义务。

使用证据建立接续前，核对它实际支持多强的关系：某种实现需要的输入，不自动成为整个机制家族的唯一前置；单次试验无改善只能否定该设置下已检验的承诺，仍须区分实现、配置、观测和混合原因，不能直接排除未检验解释。必要条件、排除性结论和不可逆排序需要相应范围的依据，否则保留竞争解释及区分它们的下一项观察。模型假设可用于条件推演，不能放宽或收紧用户明确给定的选择集合；若扩展集合值得讨论，将其作为待确认的边界变化，当前推荐仍在现有约束内。

## 3. 目标定向外部研究

外部研究默认进行。每个研究问题都应能完成句子：

> 如果答案为 A 而不是 B，我会改变哪个候选、关系、未来分支、失败阈值、不可逆成本、参与者反应、换路信号、参考类或预测？

优先顺序：

1. 当前规则、政策、价格、规格、合同或技术约束的权威一手来源；
2. 可比参考类、失败案例、反证和结果分布；
3. 行为者可能如何适应的可靠研究或直接证据；
4. 领先指标、弱信号及可验证的数据入口。

停止规则：连续新增资料只重复既有结论，且不再改变候选、关键分支、失败条件、不可逆成本或换路信号时停止。若起点本身存在重大事实争议，在 Future Clinic 内先完成能完成的事实核验；无法查清的保留为未知，并让路线显式处理该未知，不因争议而转交或退出。

深度研究后若新发现一项只有用户知道、且不同回答会实质改变安全性、当前问题模型、第一步行动或主路线的关键用户未知，先判断能否安全条件化。不能时使用普通自然语言停问：说明发现了什么、为何会改变路线、需要用户回答什么；停止依赖该未知的结论，不生成最终报告或伪完整三表面，同时继续独立证据整理与分析。用户回答是在同一已启动会诊内继续，直接沿当前对话和 Future Brief 恢复，无须重新调用 Skill；这不授权跨任务或后台运行，不保存 Case、不建立阶段状态。非关键未知继续用假设、条件分支、范围收窄或换路信号处理。

## 4. 直接呈现阶段、阶段内路径及后续

### 先确定发展的对象和坐标

本轮沿什么对象、什么时间尺度向前走？用共享底座说明它怎样来到当前、现在已知什么、能做什么，以及还受什么限制。先生成较宽候选池，再结合候选可能改变的局面，形成可修订的阶段或关键状态骨架。阶段名称用读者能理解的实际问题说明这一段要做什么，不用抽象状态词或算法目录代替发展过程，也不固定套用“准备—试验—部署”；简单任务可以很短，没有依据的历史和未来日期保留未知。

让读者先看见发展阶段，再看见各阶段里面的选择。**阶段**说明这一段要解决什么、何时进入；**阶段内路径**就是此处可选的具体做法，也可以称候选方案；各路径经过行动、反馈与后续选择的接续构成**发展路线**。不要求读者先学这套术语，不重新定义来源中的同名对象。一个阶段可含多个不同问题，每个问题下面分别比较路径。阅读先后不等于工作依赖，可以重叠、提前探索、跳过与返回。技术问题以技术选择为主体，不强制抬高成项目战略，也不统一降为支撑脚注。

### 在明确问题下比较候选

先问“此处选择什么”，再比较具体机制。区分互斥替代、可同时采用、前后阶段、类别与具体实现、条件成立后才激活的分支，以及共同能力。支撑工作说明服务谁、何时使用；取得信息的动作说明改变哪项未知；外部结果说明怎样触发后续，不能混成同一个三选一。没有多个真实选择时讲清共同过程，不制造分叉。

所有真实且决策相关的候选必须可见，并在所属阶段和问题下面直接展开。使用子标题、列表或紧邻表格，让读者无需翻其他章节或图就知道父子关系。路径名称优先说明具体动作，专业名随后解释；总览也应说明怎样做，不能只有名称、输入和目标。专业细节放在相应路径下。用户明确提出的设想，即使归为某路径的实现或共用工具，仍在所属问题下与其他做法比较机制、第一反馈及后续，不能归类后只剩共用说明中的一句旁注；材料不足处保留条件，不编造差异。

整理与归类时保留独有机制、反例、证据与适用条件，被支配或暂缓项说明理由及重新考虑条件；共同能力不冒充候选。来源若把类别或方案称为路线，沿其原义定位，不借改名清除责任。类别归并不推出合并模型、统一实现或采用门槛；这些关系须另有依据。同输入、同假设下仍可能有不同判断函数。总览压缩时核对对象、关系类型及条件方向，不用报告术语反推源义。仅当责任、机制、信息流、承诺、触发与后果均无实质差别时合并重复描述；有差别的实现仍在相应问题下比较。

不要先限定少数主路线再分配其余候选。先探索足够宽，再选择值得完整追踪的轨迹和必要的局部展开；不穷举候选的笛卡尔积。新增机制或证据可以改变阶段骨架、选择问题及候选关系，不能硬塞旧栏目。新增候选不再改变选择、机制、责任、承诺、后果或换路信号时才停止扩展。

### 沿反馈追踪候选怎样发展

跟在相应路径后面，从当时可知的信息追踪：行动或组合 → 第一项可观察反馈 → 已知事实、能力、约束或参与者反应的改变 → 下一阶段的具体选择 → 后续稳定／失败形态、组合或换路。后续可以改变实现、吸收另一候选的组件、保留适用范围或退出。汇合带着各支成果、代价和限制，不能把不同反馈合并成空泛的“继续深化”。可选支线取得有效结果时，说明带着什么进入哪一选择；未采用、不可用或失败时，说明保留什么责任、主过程继续做什么。“收缩该方案”不是主过程的去向；确实无法继续时指出被阻断部分及依据。真正共用的接续集中写，路径特有的反馈、限制和返回点就近说明，不用统一流程掩盖它们。

关键接续按第2节核其证据或明确假设。共享前置须对其下每个候选分别有据；只对默认推荐或某个实现成立的条件放回该分支，不能用它淘汰其他候选。信息探索、扩大工程、完整评价与现场启用也可能有不同条件。真实不可区分反例只约束它声明的全部可见信息及适用范围；没有检测或报告只有在相应采样与可见性依据成立时才具有排除作用。可控行动与未知结果分开，不能把未来证据倒用为当前事实。研究、部署和单次运行的时间层若交接，说明交的是什么，不把能力建设写成每次运行都要重做的步骤。

值得完整追踪的主路线必须完整覆盖：第一反馈、参与者反应、阶段演化、稳定／失败形态、最大弱点、最强反例、不可逆成本、保留的选择权、继续／收缩／切换／停止的可观察信号。两跳二阶后果只是最低检查点；继续到稳定与失败形态、下一次决策及换路条件已经清楚，再向后一层仍会改变机制、推荐或不可逆性时就继续。子分支和条件路线展开到足以理解其接续与影响。参与者有实际作用时解释其激励、负担和适应；无法判断就保留可区分的条件，不虚构反应。

### 让总览与正文都可以直接阅读

开头先用简明总览说明有哪些阶段、各阶段的问题与主要路径、现在在哪里；每条主要路径用一句普通话交代怎样做，推荐随后落在已经解释的做法上。正文沿用相同层级和名称展开，不让读者从散落的段落拼接框架。总览可以压缩篇幅，不能压掉会改变推荐的对象、条件或未知；共同护栏集中写，分支例外就近写。只有有据的先后或因果才能串成形成史。

图是可选辅助，不要求总图、流程图或文本关系图。文字本身必须讲清阶段、路径和接续，无图不阻断交付。若配图，图意与依据来自 Markdown，图、正文和推荐同步；图不得增加依赖或把未知结果画成必然，未经验证不称仿真。

交付前逐阶段阅读，而不是任选一条好懂的路径：读者能否直接指出这个阶段做什么、每个主要问题下有哪些路径、区别是什么、反馈后具体去哪？共同步骤不硬凑备选；仅有阶段词、图或技术目录都不能代替这项检查。

### 成品短例：已有讲义，怎样改进并决定后续

材料：已有纸样，可比较图解或文字解释；朗读检查随时能做，真实读者反馈尚未知。下面只示范组织方式，不是所有任务的固定阶段模板。

**总览：**先比较解释方式，再根据试读中暴露的问题决定怎样修改。当前适合用同一概念的小样比较图解和文字，而不是先宣布某一种永久最好。朗读检查可并行，不是试读的前置。

#### 阶段一：同一概念怎样解释更容易懂

- **路径A：用图解说明。**制作保留关键关系的图样，观察读者能否正确解释图例与关系。若误解主要来自标注，进入阶段二修改图例；若遗漏了文字才能说明的条件，进入阶段二比较组合。
- **路径B：用文字说明。**用短句与例子解释同一概念，观察读者能否复述条件。若卡在术语，进入阶段二修改表述；若关系仍难想象，比较加入图解。

两种小样可并行比较，已知互补时也可提前试组合，不必先淘汰一个。共同工作是试读；朗读能发现拗口，不能代替真实理解证据。未做朗读或没有发现线索，仍可带着未验证问题进入试读。

#### 阶段二：根据理解障碍选择怎样修改

- **路径C：保留单一解释方式，修局部问题。**图例或术语问题已定位时，改对应位置后再试读；若原障碍消失且没有新遗漏，保留较简单版本；若仍缺另一种表达提供的信息，转路径D。
- **路径D：组合图解和文字。**针对已知遗漏补充另一种表达，再观察理解是否改善及阅读负担是否增加；若没有增益，退回路径C；若确有互补，保留组合。

理解问题解决后，检查剩余使用障碍；新反馈指向概念表达时返回对应路径，不能笼统写“全部完善”。现在尚不知道哪种反馈会出现，以上是条件推演，不是已发生结果。

**反例：**“最值得做图文协同。图解路线／文字路线／朗读路线 → 收到反馈 → 全部完善。”它既没有阶段下的选择层级，又混淆解释方式与检查手段，统一结尾也没有说明路径各自如何继续。

## 5. 方法选择

### 5.1 基准率、区间或概率预测

只在同时具备明确可判定的命题、信息截止点与判定日期、可解释的参考类或数据、客观判定规则，以及更新条件时输出概率。在 `<artifact_stem>.md` 内只记录真正影响决策的预测；不为凑数预测。条件不齐时改写为“在 X 成立时更支持路线 A；出现 Y 时转向 B”，不要给装饰性的百分比。单次命中不能证明校准；后续结果可用于 Brier Score 或区间覆盖率，但本产品不建立跨 Case 状态机。

### 5.2 深度不确定情景

情景用于挑战策略，不是预测。只构造会改变路线排序或失效条件的 plausible alternatives：选择少量关键、不可控且确实不确定的驱动，组合成彼此可区分且内部连贯的未来，在每个未来中检查路线表现与脆弱点。删除只把同一故事改成乐观／中性／悲观语气的情景，不附伪概率，并写清它挑战的假设与观察信号。

### 5.3 定性稳健性、动态换路与 backcasting

可用小型 XLRM 骨架暴露脆弱性：用户可控制的路线、外部不确定、关键因果关系与待验证假设、成功指标与护栏。比较路线在哪些未来仍可接受、何时失败、失败是否可检测、能否及时切换和代价是否可逆；输出定性稳健性，不包装成计算仿真。

对主路线给出当前最稳健的第一步、保留的选择权、继续或加码的领先信号、收缩／切换／停止的信号、观察方式与责任人，以及哪个决定会让之后换路变贵或不可能。阈值应来自规则、数据、明确护栏或用户可判断的事件；没有依据时给事件条件，不编精确数字或期限。

只有目标未来已经由用户选择时使用 backcasting：定义可观察的目标状态与边界，倒推能力／资源／前置条件，找出最晚必须作出的不可逆决定，设计低成本验证与里程碑，并标出失败后何时重选目标或路线。Backcasting 说明怎样抵达，不证明目标本身值得选择。

## 6. 推荐、组合与分歧

在已经解释的阶段和路径中定位当前推荐，用普通话说清现在做什么、为何先做、下一反馈及重选位置。不用未解释的专业词串代替总体安排。推荐优先考虑跨多个未来仍可接受、尽早获得高价值信息、保留选择权且失败损失可控的第一步。主推荐说明最强反例、失效条件和会改变排序的证据，不把未确认偏好或外部规律当作用户事实。

若采用多个候选，明确组合、先后或条件结构及各自贡献；不能悄悄从技术选择切换成投入策略排名。推荐沿正文同一状态与反馈链成立，不使用未来证据。存在会改变选择的实质分歧时，说明各自依赖的事实及判定方法，不靠投票或静默综合消除。只有高影响、路线相似或强不确定任务才考虑不看主推荐的独立挑战；其输出是待验证假设，不是事实证据或固定生产拓扑。

## 7. 三表面交付

先确定两个相互一致的报告身份：

- `report_title`：Markdown 一级标题与 PDF 封面的完整自然标题；
- `artifact_stem`：简短、可读、能识别核心对象与本次研究目的的文件主名。

用户明确指定报告名称时优先使用；未指定时从“核心对象＋本次研究目的”自然生成。默认可带日期 `<核心主题>_<报告性质>_<YYYY-MM-DD>`。移除 `/ : * ? " < > |` 等文件系统非法字符；过长时压缩修饰语但保留核心对象和研究目的。不得默认使用 `report`、`Report`、`output` 或“未命名报告”。同目录同名时依次追加 `_2`、`_3`，不得覆盖旧产物。Markdown 与 PDF 使用完全相同的实际主名。

### 7.1 `<artifact_stem>.md`：唯一完整语义源

开头给简明、可独立阅读的阶段与路径总览，再定位当前推荐；共享底座解释当前局面的来由。正文按“阶段—该阶段的问题—具体路径—反馈与后续”逐层展开，有实质选择的阶段下面直接列路径，专业细节放在对应路径下。技术机制是用户目标时充分展开，不统一降为附录。总览、章节、推荐沿用稳定名称和关系；局部技术目录或末尾阶段表不能代替这套可见层级。图可选，不承担文字缺失的组织。

标题随任务自然调整。保留会改变结论的真实候选、参与者反应、阶段演化、稳定与失败形态、最大弱点、最强反例、不可逆成本、选择权与换路条件。共同护栏集中表达，关键例外贴在相应分叉。外部来源可点击并注明本轮信息截止时间；内部 evidence ID、Agent 收据、Schema 和审计流水不进入正文。

### 7.2 `<artifact_stem>.pdf`

从最终 `<artifact_stem>.md` 直接渲染为同主名 PDF，不在 PDF 中新增事实、路线或结论。保留阶段与阶段内路径的标题、列表和表格层次；若使用图，也须可读且与 Markdown 同义。PDF 封面使用 `report_title`，并与 Markdown 一级标题一致。使用本 Skill 自带的 `scripts/md_to_pdf.py` 和 `assets/` 中文字体；依赖与调用方式见 [pdf-rendering.md](pdf-rendering.md)。先尊重宿主提供的 Python 路径或 `FUTURE_CLINIC_PDF_PYTHON`，再寻找当前环境已有的兼容解释器；用 `import markdown, weasyprint, fontTools` 做只读探测。已有依赖先修复发现或链接问题，确实缺失时依当前授权在隔离环境安装 `requirements.txt`；不假设其他用户已有常设安装授权，不使用 `--break-system-packages`。不要重启或前台唤起 Codex/ChatGPT。

渲染时显式传入 `--author "游诗辰 · Future Clinic"`，与 Markdown 署名一致；不改写历史报告。

替代路径必须保留 Markdown 的标题层级、表格、链接和中文字体；把报告降成纯文本打印、丢失表格结构或断裂链接，不是合格降级。完成可行的授权内修复后，若仍有真实权限或环境障碍，保留完整 `<artifact_stem>.md` 与聊天摘要，明确 PDF 的具体阻碍；不得把已获授权且可安装的依赖误报为待批准，也不得把低保真 PDF 当作通过。

生成后检查 PDF 头、页数、文件大小与解析器错误；提取文本核对标题、署名、关键路线、推荐、风险、换路信号和链接语义，并确认没有遗留其他产品标签；将所有页面渲染为图像并逐页查看中文乱码、缺字、裁切、重叠、表格溢出和空白页。局部修复后重新生成，复查受影响页面及重排范围；字体、全局样式或分页改变时复查全篇。

### 7.3 聊天摘要与轻量 manifest

聊天沿用报告的阶段与路径名称，先保留让推荐能被理解的简明框架，再说明当前推荐、关键反馈及后续、最大风险／未知与换路信号，并给实际生成的同主名 PDF 和 Markdown 入口。不只给文件链接或抽象术语，不在摘要中增加结论或隐藏会反转推荐的条件。

可选 manifest 只记录 `generated_at`、`information_cutoff`、`report_title`、`artifact_stem`、实际 Markdown／PDF 文件名与 SHA-256、渲染器身份和来源数量。聊天链接和 manifest 必须引用实际名称。它验证同源身份，不代表用户接受、发布状态或现实有效性。

## 8. 失败模式与边界

- **没有现成选项**：从核心目标、证据链、信息顺序、解释框架、实施机制、未知处理和退出权中寻找真实候选；放入共同过程后再判断分歧，也可只呈现该过程及内部条件分支，不为凑数拆阶段；不得退出或转交。
- **换壳路线**：合并重复候选，保留其实现细节；不要因数量需要编造或删减真实机制。
- **证据不足**：把未知、条件和取得信息的路径写进路线，不把假设冒充事实，也不以证据不足为任务类型退出。
- **伪概率或情景冒充预测**：去掉数字，改成条件分支、挑战未来与更新信号。
- **推荐吞掉分歧**：展示实质分歧及判定方式。
- **PDF 与 Markdown 不一致**：以 Markdown 为源重新渲染，不手工补 PDF。
- **需要现实实施或新权限**：完成分析与设计后停下，明确待授权动作。

## 9. 运行记录与评价

在评估或试点中，可在输出目录另存非语义运行记录：开始／结束时间、Token（若宿主可见）、工具与 Agent 调用次数、来源数量、渲染与视觉 QA 结果。它用于比较成本与失效，不进入生产 Skill，不证明业务效果或用户接受。
