# 围绕本轮判断研究、比较与交付

本参考解释怎样完成用户本轮需要的判断：开放发现研究到足以比较和筛选，诊断与选择查清决定答案的关键证据；不是固定深度菜单、目录、字段表或方向数量规则。显式调用即开始，先复用有效 Brief 与用户输入，涉及既有项目时恢复相关历史所形成的当前局面，再核关键原始来源。深度随原题与有效澄清变化，不把所有问题转成全面工程研究。

## 1. 先确定此刻真正需要解决什么

从用户原请求与有效澄清，用自然语言恢复本轮研究对象、要得到的判断和成功含义，以及当前已知、已有投入或候选、时间/事件边界。区分当前任务、引用案例与候选手段；后续简短回复放回这个上下文理解，只有用户真正改变要求才调整目标。新增研究方向说明它怎样影响原问题中的判断，不以更宽或更易回答的问题替换目标。目标可以是理解、核验或设计，不因没有现成选项退出。尤其分清探索新办法、验证已提出的办法、选择实施策略与实施本身；不能把上一轮宽泛目标自动带到用户已经收窄的这一轮。Brief 是索引而不是裁判：最新明确指令优先，旧材料中的推荐仍只是待审视的意见。目标、约束、观察和因果解释各有作用；多个目标分别保留成功标准。纠正解释时核对整个问题，不能把对一种手段的质疑转成另一种手段的共同门槛。

共同底座连接原题、实际观测、约束、当前事实与未知。既有项目在首次筛选与排序前，沿相关记录恢复足以解释当前局面的关键转折：当时为何选择某种做法，实际做了什么、得到什么结果，最新决定改变了哪些任务，谁能决定或执行，哪些资源确实可用，以及哪些瓶颈仍在。用时间和来源区分当时事实、当前已核状态、用户报告、解释与未知；旧计划不当作已实施，旧决定不越过后来的明确变更，未找到更新不证明旧状态仍有效。已有 Brief、总结和索引用于定位，关键转折与冲突回到原始正文核对；不以“读过背景”或列出时间线代替对当前选择的解释。

按会改变本轮方向去留、比较、归因或第一项行动的线索追读，不强制全项目通读，也不为完整历史增加固定问卷。简单或非项目题只取必要背景。纵向理解要进入横向发现：从过去有效与失效的条件寻找实质不同的机制，再用当前角色、资源、约束及竞争解释筛选；历史不只是报告开头的介绍，横向发现也不能被旧候选锁死。开放探索保留有价值的不同方向和研究优先级；诊断／结果评估查清决定原因类别与修复对象的证据；方案选择查清会改变选路和交接的前提；指定解释与简单题直接作答。完整复现、公式穷尽、长程工程分解和现场效果只有影响本轮判断时才成为当前责任，不自动创建组织或新任务。

能查的先查。不重复询问已经解决的问题；只有用户知道且不同回答会实质改变安全性、当前问题模型、方向去留或第一步行动，又不能安全条件化时，才合并必要问题自然提问。真实目标、授权或取舍未决不能交给 Agent 模拟用户，也不能用内部共识填平。深度研究中新发现这样的关键用户未知，也停止依赖它的结论，不生成依赖该答案的伪完整最终判断；继续独立研究与可交付部分，用户回答后在同一已启动会诊内更新受影响对象并再审视，无须重新调用 Skill。其余未知用假设、条件分支、范围或重选信号表达。

### 研究转折处的实际往返

多轮纠错与真实取证交替进行，围绕具体对象运行，不是报告写完后补一句“已质疑”。先由原话与必要材料形成短理解和最小探索构想，交代要查什么、为什么可能改变本轮判断、已有依据与未知；能形成对象所需的最小读取或搜索可立即做。在准备明显扩大搜索、缩小候选或投入更多深度时，给临时独立质疑者审视当前对象。首次构想、初搜后的实际候选与来源、深入前的具体主张分别可能暴露不同问题，不能用开头一次讨论代替后续转折的审视；简单明确题和普通连续补读不需要一律多轮评审。

调用时提供用户原话、决定本题的原始背景或可读取路径、仍有效的 Brief 和澄清、已确认约束、完整待审对象与关键来源定位。使用不继承起草过程的独立上下文，不只传自己的摘要、辩护或想让它赞同的结论。要求它指出具体缺陷、所据原文或待取得事实，以及问题会改变哪个入口、比较、主张或投入；也允许结论为没有关键异议，不设问题数量或要求否定。等待真实返回，不把派发成功或模型声称“其他视角认为”算作取得独立意见。

对探索构想，重点查目标是否被替换、检索入口是否过早锁死、哪些最小取材能区分理解。基础探查后，把实际出现的候选及依据交回，查遗漏的作用方式、同机制包装、错误合并／排除和分类盲区，再改变入口补查。深入某方向前，提交准备证实的主张、现有证据、竞争解释及最有可能推翻它的疑点，判断值得用什么资料和方法继续。对象随实际材料变化，不把这些提示做成每题都要填的固定表格。

主 Agent 将返回的问题转为适当动作：来源已有就回读上下文，事实待核就检索、核实现、复算或按授权分析；不是把每项批评都转问用户。质疑不能替代研究，能本轮查清且会改变答案的关键疑问仍须当轮取证；反过来，也不能只沿原主张搜支持材料来消解批评。只有真实用户知道的目的、取舍或授权按前文提问，已答事项复用；问题未答仅限制依赖它的部分。批评可能错，凭原文和证据保留判断并说明理由，不追随最后一条意见丢失原约束。

证据改变前提后，修订同一研究对象及其去向：例如更换检索入口、恢复被误排的候选、缩小主张或改变下一项查证，而非只改语气。有实质修订，就把完整修订稿、改变依据、剩余疑点和未采纳批评的理由交回质疑者，同时保留原始背景与成立的约束；原实例不可续接时将这些材料交给新的独立实例。取得实际返回，核旧问题是否解决、新问题是否出现，再决定继续查证、提问、修订或进入下一项工作。

不规定固定几轮，不靠自评分、票数或双方一致判断成立。仍有会改变方向或投入的具体疑点就处理；缺事实时转向事实，缺用户决定时保留该依赖。返回没有新的关键问题、仅重复已处理意见或调整表达，就结束该段往返；进入下一段研究不等于全部事实已证实。独立能力不可用时说明限制，实际采用单 Agent 分开起草与质疑等轻量方式，不冒称独立完成或等效。普通研究分工与临时质疑按需要使用，不建固定人数、组织、跨任务消息链或多套台账。

## 2. 保持事实强度与适用范围

区分已核验事实、用户观察/偏好、外部一般规律、模型假设及未知；进一步辨明已有不利证据、尚未查到、尚未发生与尚未测试。未知不自动记成劣势，也不自动给候选加分。一般研究不能证明这个用户、这个系统或这个现场的效果；来源冲突及其决策影响不得抹平。保留来源中的对象、数量、时间、逻辑条件和确定程度：未提及不等于不存在，稀少不等于零，当前截面不证明趋势，线索或评价责任不等于已标注样本。趋势需口径可比的基准，动机与历史不能为填框架而编造。

方向依赖历史、聚合或样本比较时，输入资格同时取决于字段语义与取得范围。记录存在、单对象可查、完整窗口可导出、其他对象可枚举和总体可重建不是同一能力。按当前已知对象取得的历史受当前选择影响，不自动代表历史总体或无条件背景；比较的覆盖、选样方式和分母须与输出主张匹配。评价对象从原目标确定，不暗加“先有明确意图、已参加或已取得输入”等条件来缩小责任；不同做法也可能改变需求形成和参与机会。需要局部组指标时单报，并说明未覆盖部分怎样限制原目标结论，不把所有对象强迫变成参与者。第一次筛选／排序前核已给接口与实际可取得范围，题面未给的能力保留未知：分别说明现有范围内的较弱实现、额外能力成立后的分支及会改变优先级的条件，不擅自升级成低输入默认，也不以某个总体版本缺输入否定整个方向。能安全条件化时继续独立研究，不为这项检查增加固定问卷。

候选关系中的依赖也是事实主张。某一实现需要额外输入，不证明整个机制家族都必须等待该输入；概念探索、扩大工程、完整评价与现场启用也可能有不同前置。单次设置无改善，不直接否定尚未检验的实现、配置或机制。类别归并不自动意味着相同模型、联合实现或统一准入条件。同输入下仍可有不同判断函数。必要条件、排除及不可逆排序，须有相应范围的证据，否则保留竞争解释并设计区分观察。

原有评价范围、期限、责任与成功标准不因候选输出而改变。不确定、保守、不触发或暂缓，不是删除原对象或失败记录的理由；输入确实无效时按既有规则核证并保留原记录。多维取舍不能偷换成单项前进门槛。假设不能擅自收窄或扩张用户明确的可选范围；值得扩张的部分单列边界变化，不作为已获授权条件。

可控行动与未知结果分开。推演到某个时点时只使用届时可知信息，不能拿未来反馈支持当前推荐。研究期真值、部署后数据与单次运行可见信息不能相互顶替。相同护栏集中写；会反转选择的例外与反证贴近相关论点，不藏在附录，也不反复把每段写成免责声明。

## 3. 从不同入口发现，让证据推动查证

默认做目标定向外部研究：某项答案改变哪个候选、关系、后果、失败条件、成本、参与者反应、参考类或换路信号？优先权威一手来源、反例与可比失败案例，必要时查询行为者怎样适应或信息怎样取得。时间敏感事实核验并注明截止点。若提供了冻结材料且任务要求只用它们，则尊重输入边界，不以重新联网悄悄改变对照条件。

先把用户所说的名词还原成需要完成的作用：谁需要理解、发现、协调、判断或改变什么，在哪些信息、时间和资源条件下完成。这样的动词表达用于找研究入口，不改变原目标或把多个功能强行并为一项。由不同功能寻找其他领域处理同类问题的具体方法，再比较其作用机制、所需输入、失效原因及迁移限制；相似措辞或跨界标签不构成可迁移证据。

以原题的任务与结果、观测类型和有效约束找问题词，再视需要扩到相邻场景、同类数据的其他用途、完整系统、成熟实践与失效案例。这些是不同发现入口，不是每题必须填满的分类表。遇到有价值的原文，沿相关工作、比较基线、作者后续和竞争解释找具体做法；同时继续不依赖首篇论文名或熟悉算法名的检索，防止全部候选来自同一引用圈。新机制装不进初始分类时修正分类。

广度同时有判断机制与具体实现／系统证据两层。已有算法名不证明已覆盖某个系统的观测形成、输入处理、集成、条件和实证；新品牌或同机制多篇论文不自动各占一个方向。同一家族因观测、假设、成本或实现差别值得分别比较，说明差别改变哪项判断。还原原始材料优势形成的完整作用链，配套能力、取得与集成条件、资源或支持若影响成本、风险或可行性，也进入比较。它们在新场景成立需独立依据，不搬用原案例成绩，也不强迫每题凑齐因素。

对去留关键的主张，连接具体做法、输入／约束变化与原目标，核必要条件、强反例和证据支持到哪一环。实现主张沿实际调用入口、默认值和条件分支核对，强模式不能概括为默认保证，关键例外与前置须限定范围。没有效果保证不代表可查解释已完成，局部机制成立不代表用户结果成立。起点有争议先核可查部分，不把争议当退出理由。正文链接说明来源实际支持哪项做法或限制，引用本身不证明适用。

关键经验和版本主张要建立来源关系：首帖与同一作者后续、问题与回复／关闭依据、文档承诺与对应实现。沿这些关系核条件、结果变化和反例，再决定原主张仍支持什么。围绕关键对象与主张，在允许的原始资料范围内检索相关出现并回读命中正文与上下文；标题／文件头／索引不替正文判断，不据它们直接排除资料。否定后续或反例存在前核实际检索范围、命中与读取覆盖，相关但未读取的资料不等于没有资料。取得失败、显示截断、只读摘要、尚未关联与来源中确实未提供分别记录；一处解析、提取或访问失败只限定对应片段，不把它扩大为整个后段或其他数据块不可取得；沿仍悬空的关键主张换定位与读取方式，核其余可读材料。已有环境还能通过定向搜索、解析或补读解决的先完成，不将未处理线索声称为不可取得。此检查按关键主张需要进行，不穷举每位作者或全部历史。

读到新证据后，分别检查原题必要判断仍有哪些缺口，候选池还有哪些未经检查的发现面；选择能改变去留或答案的检索、下层原文、后续、代码核对、计算或同口径比较。第一条可行路线的内部缺口不是后续查询的唯一中心；一项方向判断已有足够依据时，优先查可能遗漏的重要做法。查询只带来重复资料时换入口或核原文，搜索失败说明实际尝试与范围，不声称全网没有证据。

遇到“没有输入／没有结果／不支持／无法使用／结果异常”等决定性现象，不停在症状统计或能力宣称。先列仍会改变答案的竞争解释，选择能区分它们的对象、窗口或关键分支，沿相关来源、取得／生成、传递处理、实际消费或评价边界取得证据。已有代码、配置、权限原文、原始记录和历史回执能回答的先查；必要时只读复算或使用隔离探针，不因此修改业务。边界由待判解释决定，不固定审遍每层；先用有区分力的小检查，其他对象可能异因或结论涉及整体时再扩大。单段成功、已启用能力与端到端成立分别证明，按设定正确与现实有效分别判断。

无法从允许材料重建原因时，保留已尝试范围、具体缺失、剩余解释及各自支持的行动，给条件结论和最小解除条件。当前实现不自动证明历史运行；没有原因日志也不自动证明来源为空。只有新的事实、未获授权的外部动作或现场试验才能区分时，在该依赖边界停止，不编根因，也不为消灭未知无限搜索。

对每项准备交后续的查证，核它是否会改变当前答案或第一项行动、证据是否现成可访问、能否通过本轮已授权读取、检索、计算或隔离诊断取得。若能就当轮完成。对“先做A才能查B”分别核原因判别、效果评价和工程实施的真实依赖；修复评价器可能是重新排名前置，却未必阻断当前冻结输入的原因核查。研究期的连续查证补足今天的回答，实施后的未来推演处理之后反馈，两者不能互相顶替。不影响本轮判断的深入问题与确实依赖新增事实、外部行动、现场效果或授权的工作可交后续，说明影响与解除条件。

多个重要发现面或缺口可独立查证，且宿主与授权允许时，可临时并行研究或工具调用。按问题和实际方法分工，给共同目标、不同入口或负责问题、要使用的资料与方法、必要背景及权限边界，要求可回查依据、条件、反例与未知，避免各分支只在首篇论文周围加深。引入其他领域要执行该领域有用的分析，而非模仿某位专家的语气；角色名本身不增加覆盖。主 Agent 核关键原文、辨别转载、处理冲突与漏项，再补查；不拼摘要或让分支都证明预定结论。顺序依赖强或收益低时单 Agent 更合适，不规定固定人数、角色或每题必委派。

开放发现收敛时，重要独立入口已经检查，已出现且可能改变去留的线索已处理，不同入口的新结果主要重复已有机制；入选方向的证据、比较与交接足够，剩余未知的范围及影响明确。若新线索仍可能增加重要方向或改变排除理由，就继续本轮可做的查证。指定核验与解释按原题获得有据答案收敛，不强制广搜。停止无需穷举全网，不制造确定性，不因首个可行方案、已有推荐或篇幅结束；仅剩一个有据方向时说明其他可能性为何未保留，不为广度虚构候选。

## 4. 辨明候选关系，以共同口径初筛

先展开较宽候选池，再问各候选在回答什么问题、位于什么时间尺度。完整推进策略、互斥替代、可同时采用的组件、共同能力、类别与具体实现、前后阶段、条件分支、外部结果，不应混成同一菜单。条件成立后才可实施的分支也可能现在就能核验前提；不可把部署门槛前移为所有研究的门槛。

所有真实且决策相关的候选必须可见。用户明确点名的办法，即使是某条路线的局部实现，也保留其具体做法、独有机制、差异与验证安排；“已归类”不等于已经回答。被支配、合并或暂缓的说明理由和重选条件，不删除独有反例。只有机制、责任、信息、承诺及后果没有实质差别时才合并重复描述。

需要安排推进或评价时，从候选关系说明行动与反馈怎样发展。阶段表达实质状态变化，先后依赖需依据，允许并行、重叠、回返与条件激活。同一候选跨阶段保持身份，交代能力、证据和限制变化，不重新列同名路径或压成不可分叉时间线。研究、现场生命周期与算法内部事件交接具体成果，不能互相顶替；横向初筛不要求先构造每条完整生命周期。

按相同目标、有效输入、评价范围、共同基线和成本口径比较方向。分别判断做法存在、适用于当前项目与值得优先的证据。公开案例、联系方式或能力说明可证明存在，不自动证明当前能取得关键输入、资源、合作或响应；项目适用要核当前必要条件和实际作用链，优先级还需与真实替代按同一目标比较增量、代价及失败风险。证据只支持查证或试探时，先完成本轮可做的区分查证，再比较研究价值、信息价值、成本与保留的选择权，明确建议的是验证顺序而非已证实的效果排序。共同数据处理或评价基线说明服务关系，不伪装成竞争方向；技术问题不必抬成管理战略。简单基线值得比较，其失败可能是信息无价值，也可能是规则未表达关键交互；复杂方法若有具体理由能区分两者，可进入有边界研究，不继承未证明的效果，也不只因复杂而入选。

项目已有相关试法时，把重要候选与旧试法放在同一因果链上比较：过去的对象、入口、输入、关系、资源、激励或成本中，哪项条件导致了已观察的结果；新做法究竟改变了哪一环，变化有何依据，原失效原因还会不会出现。不要求每题逐项填写这些因素。每条重要推荐应交代与旧方法的关键差别及证据支持范围；只是换名称、说法或包装，不能直接算新机制或提高优先级。历史未查清时只说明已知结果与竞争解释，不编造失效原因。条件确实变化、且变化与旧失效原因有关时，可以重新考虑旧方向；局部失败或低成功率不能否定全部同类实现，过去失败也不能被泛泛“这次不同”抵消。

依据机制、可能增量和关键未决问题，说明值得继续比较、条件保留或暂不继续的去向及重选条件。缺实证不自动等于无效或值得入选；某一实现的输入门槛不扩大为整个家族的门槛。新增线索若改变机制、责任、比较或去向，修正方向集合；不穷举组件排列。研究优先级不冒充实施效果排名，验证多个候选的策略也不意味着唯一候选获胜。

用户更新约束时，先回读受影响的关键比较正文、原始资料和已有能力，不只看旧报告的开头、结尾或候选标签。把新事实作用到具体前提，说明哪些方向真被排除、哪些只需换实现、哪些仍可成立或更有利；不因排除一种实现丢掉整个方向。连接、存储、处理、通知或保存责任若是不同维度，分开比较再说明组合，不将一个条件当作全部设计的答案。能安全条件化的新语义保留分支；不能安全条件化的真实用户选择才提问。选择前完成可查的关键区分，未经比较不得宣布路线收敛。

## 5. 深到足以完成此刻的判断

需要突破常规办法或未经证实的能力上限时，用明显更有挑战的目标作研究探针：若要实现它，必须改变哪项方法、输入或前提？追查有依据的可能性和限制，把它与用户已确认的成功标准分开。挑战应带来不同的研究或证据，不能只把承诺、数字或语气加大；明确的简单题也无须这样重构。

专业深度由实际材料和方法体现。根据待判问题找到尽可能接近生成过程的原始记录或一手资料，采用能区分解释的专业分析；例如需要估计和比较时用适当的数据查询、统计方法或模型，需要检查结构与行为时用相应的专用工具或计算，而非只整理成文字表格。先核数据粒度、工具能力和可取得范围，再在授权内实际使用；只列工具名、假装已经分析或为显得专业强用复杂方法都无益。检验关键假设，寻找原先未识别且会改变判断的信号或解释；没有新发现也如实报告，不能制造新颖性。

检验成果时寻找独立于本次生成判断的反馈：可复查的计算、独立测量、未参与构造的留出资料，或真实使用者、领域同行的具体反馈，按主张选择。工具运行结果、资料外推与现场有效各有支持范围；错误评价器或不相干反馈不能证明结论。自我评价、另一 Agent 的赞同或模拟用户意见不算这类外部检验。当前可取得且会改变本轮判断的反馈在授权内取得；若依赖新资料、现场行动或未获准的外联，保留限制与解除条件，不以追求深度扩大权限。方法、工具、原始资料与外部反馈按需要组合，不建立每题必做的固定阶段。

深度按本轮责任判断，不以报告长度、来源数或后续研究者能接着查为共同终点。开放发现的入选方向应能比较和筛选：机制、现实输入、相邻差别、原始证据支持范围、强反例与未决问题足够清楚。诊断和结果评估须对会改变归因或修复对象的异常完成可取得的区分查证，讲清现象、原因证据到哪层、影响什么结论、应修或保持什么，以及真实剩余依赖。方案选择须说明选择依据、最强替代、已有／缺失能力、关键接口责任及必须由用户决定的事项；普通实现细节由实施者处理，不预写全部代码。指定核验与解释按该题直接完成，不强制扩宽。

报告为各入选方向保留足够独立使用的交接说明：共同原题与有效约束、方向的具体主张与机制、关键来源及定位、竞争方向及共同基线、尚未解决的问题、希望取得的结果，以及结果怎样导致继续、收缩、换路或停止。共享背景复用，方向保留自身差异；不把论文名或共用组件当独立方向，不交出只有名称的清单，不另建多套台账。返回的新证据若改变横向判断，更新方向集合与优先级；交接本身不授权启动深研会话或实施。

逐项审视“以后再查”：会决定本轮答案的原文、前置、原因解释、计算或反证当前能做就完成；与当前判断无关的公式穷尽、完整复现和长程工程分解可交后续。真正缺证据时收紧结论并说明解除条件，不冒称已经定因或选路。交付前设想用户说“按这个做”：第一步若仍需重新研究报告声称已解决的原因、路线或关键前提，就补研究或限定结论。常规实施现场核对、新输入验证及实际部署不因此变成本轮义务。不存在统一字数、每方向同等篇幅或固定追加研究次数。

用户要求选择或证据足以支持选择时公平比较并推荐，不强迫所有探索最终选赢家。完整主路线推演按实际需要启用，连接行动、第一项可观察反馈、状态和约束变化、后续选择、稳定或失败形态；讲清最大弱点、最强反例、不可逆成本、选择权和继续／收缩／切换／停止信号。最强竞争路线展开到足以挑战推荐，指定逐项验证的责任保留，参与者确有作用才分析其反应。两跳是完整未来推演的最低检查点，后续仍会改变判断时继续；它不是每个横向方向的篇幅门槛。

方向被反证、暂缓或局部实现失败时，说明原问题怎样继续、哪些责任未解决，不能把“停止这一实现”当成目标消失。组合说明各自贡献与成立条件，不以合并名称取代机制比较；反馈返回后可换路，不以“全部深化”统一处理不同结果。

## 6. 研究优先级、最终选择与未来反馈

开放发现推荐值得深入的方向集合与研究优先级，依据原目标增量、证据条件、区分问题的信息价值与成本，保留真实分歧和条件候选。诊断、更新和指定题直接给相应判断。用户要求选择时也按实际证据给出取舍：比较足够就推荐当前较稳健、保留选择权且失败损失可控的第一步，并解释最强替代何时更好；证据仍不足以支持项目适用或效果优势时，保留条件比较，推荐能以合理成本区分关键未知的动作，并说明为何先验证它、观察什么、什么结果会使它升降级。低成本和可逆性可支持先试，不自行证明更可能成功。不先写“首推／最靠谱”再用未验证的免责声明抵消，不因缺少现实保证拒绝所有行动，也不以“都不确定”回避已有证据支持的差别。多候选并用说明组合、先后或条件及贡献。反证击穿推荐就修改，不靠投票或静默综合消除分歧。涉及竞争优势时分别分析使用效果、收益归属、持续条件与替代代价，不能把一项目标作为其他目标的门槛；有实际影响的参与者适应再推演。

深度不确定时用少量真正能挑战策略的情景，不只改写乐观/中性/悲观语气。情景是挑战，不是预测。比较哪些未来仍可接受、何时失败、是否及时可见、能否换路及代价。观察方式与责任有依据才具体化；阈值来自规则、数据或明确事件，不编精确数字、时间或人物。

只有命题可判定、参考类或数据可解释，并具备信息截止点、判定日期、客观规则与更新条件时才给概率。影响决策的预测及更新条件保留在 Markdown 内；单次命中不证明校准。条件不齐用条件推演，不给装饰百分比。用户已选定目标未来时才用 backcasting 倒推能力与不可逆节点；能倒推出路径不证明目标值得追求。文化或象征性解释明确不是科学预测，不虚构必然事件。

## 7. 报告从读者需要出发

阅读从用户所需判断开始。开放发现先给方向集合、关键差别、入选／条件保留／暂缓的依据和研究优先级；诊断／结果评估先说现象、原因支持范围、影响与修复归属；更新说明新条件怎样改变旧比较和去留；核验、解释或指定研究直接答原题。方案选择再讲推荐、最强替代、已有／缺失能力、第一反馈与真实待决事项。随后沿共同基线、具体做法、原始证据和分歧推进；项目题在相关论点中连接历史选择、当前瓶颈及本次条件变化，让它们解释候选去留与推荐强度；需完整主路线时再展开其发展。标题按内容自然命名，不将所有问题套入推荐目录。

保持稳定名称，让候选关系、主线阶段和推荐描述同一过程。细节扩充主论证，而不是每到一个阶段又重开新的路径菜单。共性集中写，关键例外就近写。若技术差别决定取舍，就留在正文，不为了“策略感”隐藏它；不影响当前判断的运行流水、版本哈希和审计记录才放附件。没有字数或页面指标，删重复不删责任。

给信息清楚的归属。开头回答与导航，不预先复述所有实验；方向比较处完整解释机制、关系、条件与初筛，待深入问题及反馈去向放在该方向最合适的位置。完整主路线启用时，相关阶段再说明具体验证与后续。共享背景和评价口径集中表达，不把相同交接和验证复制到末尾行动表、预测账本及风险清单；结尾需要提醒就定位已有正文。数字与技术细节按对判断的作用保留，不因已核对全搬进正文。

完成初稿后从头连续读：新一节是否推进了判断，还是换名称复述前文？去掉重复仍应保留候选身份、机制差别、指定验证责任、决定性反证及反馈后的去向。可读性由这样的组织改善，不靠删难题、任意字数上限或另写一份更好懂的聊天来获得。

图是可选辅助，不是交付门槛；必须与文字同义，不能补造依赖、结果或假确定性。未经计算和核验的推演不叫仿真。

### 一个简短示意：已有展览讲义怎样改进

用户已有纸样，考虑图解、文字、两者结合，能做朗读检查，真实读者理解未知。图解与文字是解释方式，组合可能互补；朗读是共用检查，试读是获取理解反馈，不能当成四五条同级路线。

当前可推荐先对同一难点制作图解与文字小样并试读，而非立即重做全册。先比较单一表达，若分别暴露互补遗漏，再做针对性的组合；若只是术语或图例问题，先局部修复并复试。有效结果支持逐步扩展到其他难点；若改过后仍误解，返回概念取舍而不是堆更多形式。朗读可并行，不能代替真实理解证据。

最强替代是直接做组合稿：若已有读者证据确认两种表达缺一不可，它可能更省时间；但现阶段这种证据未给，直接重做增加无效工作和阅读负担。这解释了当前推荐，也说明何时反转。它不是每个任务都应采用“两小样再组合”的规则。

## 8. 同源交付与检查顺序

先确定 `report_title` 和 `artifact_stem`：用户明确指定报告名称时优先使用；未指定就按对象与研究目的命名，可附日期。移除 `/ : * ? " < > |`，不要默认使用 report/output。Markdown 与 PDF 使用完全相同的实际主名；已存在时追加 `_2`、`_3`，不得覆盖旧产物。Markdown 一级标题与 PDF 封面同为 `report_title`，署名 `游诗辰 · Future Clinic`，聊天链接引用实际名称。

Markdown 是唯一完整语义源，PDF 从最终 Markdown 直接渲染，聊天摘要不另增框架或结论。聊天讲清同一直接回答及依据；开放发现带上方向集合、初筛与待深入问题，最终选择说明推荐、关系、反馈、风险和换路，再链接实际文件。可选轻量 manifest 只记录文件身份、时间与哈希，不承载独有语义，不代表接受或现实有效。

PDF 使用本 Skill 的独立渲染器，见 [pdf-rendering.md](pdf-rendering.md)。显式传入 `--author "游诗辰 · Future Clinic"`。提取文本核对标题、署名、推荐、关键机制、风险、后续及来源链接，再逐页查看中文、裁切、溢出、表格与空白页。修复后复查受影响重排范围；全局字体或样式改变则复查全部。尊重宿主提供的兼容环境，先诊断发现/链接问题，再按授权安装最小依赖，不以重启桌面应用解决依赖。不把丢表格和链接的纯文本打印视为合格 PDF。

在生成PDF和摘要前，先核原题必要判断已经完成或被证据限制得当：关键异常是否仍停在症状、条件更新是否漏读旧比较、后续建议是否把当前可查责任转交、先后依赖是否真实。若用户说“按这个做”，正文应足以支持该轮应有的行动，不需重新做它已声称完成的核心判断。排版成功不是研究完成证据；后续真正依赖新增事实、现场验证或授权时给条件结论和解除条件。

报告开头按实际任务直接回答：开放发现呈现可比较、可交接的方向集合，诊断／结果评估说明因果证据与修复对象，更新说明旧结论怎样改变，核验限定成立范围，解释讲清机制，选择给相应路线依据。未来推演服务于原问题，不把所有任务改成完整主路线研究。

先从用户原话与有效澄清独立确定成功要求，再由原题、实际观测与原始材料反查发现盲区：重要机制、具体系统证据或指定责任是否消失，是否只围绕首条路线查缺口？排低理由是否误扩某一实现的条件？项目历史和最新状态是否实际约束筛选，重要推荐是否说明相对旧试法改变了什么及依据，还是仅换包装重推？做法存在、当前适用与值得优先是否各有相应证据，验证动作是否被误写成效果优势？本轮仍可做且会改变答案的查证先完成，不能仅在末尾承认缺口。再只读正文核候选关系、共同基线、入选／暂缓理由与每个入选方向的交接是否足够；指定或简单问题是否直接完成，最终选择相对最强替代是否成立，所需未来过程是否可追踪。最后核事实、反例、表达与同源文件。没有阶段词不自动失败，有阶段词、方向数、来源数、格式测试、哈希或图也不证明研究质量。

## 9. 研究与现实行动的边界

研究默认不授权发送、购买、部署、业务修改或现场实施；有明确实施授权时按其范围行动，不能因研究方法扩权。关键事实不足可以先验证条件，不把未知当取消候选的理由。真实权限或环境障碍只阻断依赖部分，保留独立成果并说明缺口。不要建立跨任务状态机、历史 Case、Runtime、Hook 或固定 Agent 拓扑，不修改无关配置或其他产品，不退出、重启、重装或前台唤起 Codex／ChatGPT。
