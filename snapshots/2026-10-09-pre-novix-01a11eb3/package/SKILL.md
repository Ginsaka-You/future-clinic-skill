# Future Clinic

只在用户显式调用 `$future-clinic` 时运行，一旦调用就无条件启动 Future Clinic。没有 Brief、现成选项或可控决定，也不退出或转交其他方法。先读 [future-decision-method.md](references/future-decision-method.md)，再围绕用户真正要推进的事开展研究。

核心是精准回答用户本轮问题，并解释当前判断怎样影响后续推进。需要选择时，从共同当前局面辨明候选关系，公平比较并推荐主路线；需要更新、核验或解释时先完成相应回答，不强行改造成方案选择。未来推演解释行动与反馈怎样改变后续判断；阶段由真实依赖与状态变化产生。

## 研究：让关键缺口推动下一轮查证

1. **保持本轮问题。** 从用户原请求与有效澄清恢复研究对象、要得到的判断和成功含义，区分本轮任务、引用案例与候选手段。后续简短回答放回这个上下文理解，只有用户实际改变要求才调整目标。新增方向须说明它改变原问题中的哪项判断，不能用更宽或更容易回答的目标替代原目标。当前对话或给定路径存在 Future Brief 时先读，复用仍然有效的目标、用户输入、偏好、护栏和来源索引，不重复询问已经解决的问题。Brief 是目标与输入索引，不是外部事实的证明；与最新用户要求或原始材料冲突时明确纠正。分别保留用户目标、明确约束、已有观察与因果解释；反证一种解释不撤销目标，一个目标的门槛不自动约束另一个。已有候选要验证，就承接这些候选及其验证责任，不重置成泛泛探索“更好的办法”。没有 Future Brief 时仍无条件启动，做一次快速就绪检查。
2. **形成共享深度诊断底座。** 读取相关原始材料，讲清当前事实、未知与边界；纵向追踪形成与演化机制，横向比较竞争解释，找出交叉位置的矛盾和驱动力。第一次排序前，沿原始材料的完整作用链追出可能改变结果的不同机制、成立条件与迁移限制；不只保留直接改变核心输出的部分。关键主张追到具体做法怎样改变输入、约束或资源，怎样影响原目标，成立条件、强反例和证据支持到哪一环；据此更新答案。实现承诺须沿实际入口与调用链核对默认值、模式和条件分支，不只读实现定义；某一配置或强模式的能力不能概括成默认、所有模式或完整作用链的保证。关键例外与前置查清后再确定主张范围。深度以支持所需判断为准，不写无关全史。默认做目标定向外部研究，优先一手来源和反例；时间敏感事实须核验并注明信息截止点。
3. **展开候选，辨明关系。** 从较宽候选池开始，识别完整策略、互斥替代、可同时采用的组件、共同能力、类别与具体实现、前后阶段以及条件成立后才激活的分支。候选广度由机制差别和目标覆盖判断，新增品牌不等于新增机会；所有真实且决策相关的候选必须可见。既不把阶段当并列方案，也不把真实替代硬排成先后；归类、暂缓或合并不能抹掉独有机制、反例与用户指定的验证责任。共同步骤集中解释，不各占一个主路线；没有真实分歧就讲清共同过程，不凑路线数。
4. **由关系安排阶段并比较整体路线。** 说明每个候选从现在怎样发展、什么反馈允许下一步、哪些工作可并行或只在条件成立后采用，再比较有实质取舍的整体策略。阶段数、路线数与粒度由问题决定，不要求每阶段都列一组路径。按相同目标口径比较，区分不利证据与尚未查明；支持候选存在不等于支持它排第一。比较足以支持选择后暂定推荐；排序依据不足时找能区分候选的查证，说明信息价值与成本；本轮可做且已授权的先完成，再决定什么确需留待以后。新证据可改变阶段、关系与推荐。主路线可以是协调验证多个候选的策略，不等于选定唯一算法或产品。
5. **按决策作用分配深度。** 推荐路线完整追踪行动、第一项可观察反馈、状态与约束变化、后续选择、阶段演化以及稳定／失败形态；解释最大弱点、最强反例、不可逆成本、保留的选择权和继续／收缩／切换／停止的信号。有实际作用的参与者再分析其反应，不虚构人物。最强竞争路线展开到足以推翻推荐，其他真实备选写到足以公平比较与重选。子分支、局部实现和共用能力紧凑表达，不平均写成许多小会诊。核心机制须连接具体做法、输入或约束变化与用户结果；能查的解释、可计算关系和条件推演先完成，再定位实测缺口。研究中的连续查证与实施后的未来反馈互不替代；两跳只是未来推演的最低检查点，继续到后续决策和失败去向清楚。
6. **依据推演修正推荐。** 推荐当前最稳健、信息价值或选择权较好的第一步，不宣布永久赢家。多个候选并用时，说明组合、先后或条件结构及理由。决定性分歧与反证直接展示，不以静默综合消除；未知用条件推演处理，不拿未来结果为今天背书。预测与情景的方法及事实范围见参考文件。

对承担关键判断的经验、版本或实现主张，把相关来源接起来核查：可查的原文／下层实现、同一作者或项目的后续、相反结果和成立条件。围绕关键对象与主张，在允许的原始资料范围内检索相关出现，回读实际命中的正文和上下文；标题、文件头和索引只用于定位，不能代替正文判断或据它们把资料排除为无关。后续改变了原主张就更新其证据身份，不能继续把早期成功当作当前成功。作“未见后续／反例”等否定判断前，核对实际检索范围、命中与读取覆盖；未处理的已有资料不能成为不存在的证据。区分真正不可取得与尚未打开、截断或未关联的已有资料。一处访问、解析或提取失败只限制对应片段，不证明其后或其他数据块不可读；围绕尚未回答的关键主张换定位、解析方式或补读范围，核剩余可读材料。已有资料在允许范围内先补读与交叉检索，不能写成环境不支持或交给以后。

读到新证据后，围绕尚未回答的关键问题选择下一项检索、原文与作者后续回读、实现核对、计算或比较，并用结果更新后续问题。能实质改变答案、且本轮可做的已授权查证继续完成，不仅写成建议用户开展的下一步。需要新用户事实、外部行动、现场试验或确实不可取得的证据才留为后续，说明尝试、限制及其影响的判断。关键问题已有有据答案，或关键未知在当前确实不能继续缩小，主要竞争解释与反例已处理，才收敛；不按固定查询次数、已有推荐或篇幅停止。

多个重要问题可独立研究，且宿主与授权允许时，按问题责任使用临时研究子 Agent 或并行工具；顺序依赖强或分工收益低时保持单 Agent。委派给出共同目标、负责缺口、必要背景与边界，返回可回查依据、条件、反例及未解决点。主 Agent 负责综合、复核关键原文、处理冲突并补查；不以分支摘要拼接或人数代替判断，不建立固定人数、固定专家组织或跨任务流程。

能查的先查；只有用户知道、会改变安全性、当前问题模型、第一步行动或主路线，且不能安全条件化的关键未知才自然提问。深度研究新发现这种关键用户未知时，停止依赖它的结论，不生成最终报告或伪完整交付；继续独立工作。用户回答后在同一已启动会诊内继续，无须重新调用 Skill。非关键未知用明确假设、条件分支或换路信号处理，不做固定问卷。

## 报告：让读者跟着一条论证走

研究顺序不等于阅读顺序。开头直接回答用户原问题：更新了什么、哪些主张成立到什么范围、关键机制怎样起作用，或当前选择及理由。选择任务再说明为什么优于最强替代、先取得什么反馈、什么情况会改主意；其他任务围绕所需判断解释后续影响。随后沿一条论证展开依据与关键分歧，不让读者从路线中自行拼答案。候选的具体做法须在支持判断时说清，不能只列专业名称。

主线名称和候选身份贯穿总览、正文与推荐；同一候选跨阶段说明它怎样演化，不反复重开“路径一二三”。阶段应在路线推进中清楚可见，但不统一要求“阶段—问题—路径组”目录。技术机制是问题核心时充分解释，不一律降为组织策略或附录。完整性不是平均篇幅；清晰也不能靠删掉难解释的候选取得。

每项论证在最合适的位置完整展开一次。开头承担推荐与导航，不压缩复制全部实验；候选关系处解释区别和取舍，主路线对应阶段说明具体验证与反馈，结尾只收束当前动作和下一决策，不再复制一套候选清单、验证账本或风险表。共用护栏只说明一次，后文仅写真正不同的例外。历史数字只保留会改变当前选择的部分，其余有需要再引来源。报告应是逐步推进的论证，不是分析笔记、检查记录和摘要的拼接。

事实、用户输入、外部规律、假设与未知保持边界。局部失败不扩大为家族无效，某个实现的前置不升级为所有候选的门槛，原评价范围、期限、逻辑条件和责任不随推荐改变。共同护栏集中写，会改变取舍的例外就近说明；版本哈希、执行日志和内部评审放证据附件，关键反证不能藏到附件。

图是可选辅助，无图不阻断交付；若画，必须与正文同义。不得为了图形、固定阶段数或路线数扭曲关系。

## 同源交付

先完成唯一语义源 `<artifact_stem>.md`，从它派生同主名 PDF 与聊天摘要。摘要概括同一直接回答及其依据，需要选择时带上推荐、候选关系、第一反馈、后续与风险，不能补进报告没有的总体框架。报告署名统一为 `游诗辰 · Future Clinic`。

`report_title` 为 Markdown 一级标题及 PDF 封面标题；`artifact_stem` 为能识别对象与研究目的的文件主名。用户明确指定报告名称时优先使用；否则自然命名，可带日期，移除 `/ : * ? " < > |`，不默认叫 report/output。Markdown 与 PDF 使用完全相同的实际主名，同名已有文件时追加 `_2`、`_3`，不得覆盖旧产物。聊天链接引用实际名称。

用本 Skill 的 `scripts/md_to_pdf.py` 渲染，不依赖其他 Skill 的脚本或字体；操作与依赖说明见 [pdf-rendering.md](references/pdf-rendering.md)。显式传作者，检查文本、来源链接和报告身份，并逐页查看 PDF。只有真实环境障碍仍无法排除时，交付完整 Markdown 与摘要并明确 PDF 缺口，不把低保真替代当完成。默认写当前任务独立输出目录，不污染历史报告。

## 交付前检查

先依据用户原话与有效澄清独立确定本轮必须回答的判断，再对照报告与原始来源：是否保持本轮对象和成功含义，逐项给出有依据、强度合适的答案？原始材料中的关键目标、机制和指定责任是否仍在？还有本轮可做、会实质改变答案的重要查证吗？有就继续，不能仅改写结论。再只读报告本体：候选完整且关系正确吗？排低理由是否适用于候选实际解决的问题？读者能说明为什么选这条主路线而不是最强替代吗？能沿推荐看到行动、第一反馈、后续分叉与换路吗？指定候选的验证责任还在吗？这些答案必须来自正文，不靠读者跨章节重建或聊天补救。

再检查决定性事实、反例与条件强度，以及三表面的语义、署名、文件和 PDF。有阶段词、图、来源链接或通过格式检查，不等于论证成立。概率缺少参考类、截止点、判定日期与规则时不用数字；文化或象征性解释注明非科学预测，不虚构必然事件。

## 授权边界

会诊默认只研究、分析和设计，不执行购买、发送消息、修改业务、部署、发布、删除或迁移；明确已有授权按其范围执行。最小依赖安装遵守宿主授权，优先修复已有环境的发现问题。不得创建历史 Case、Runtime、Hook、Ledger 或固定 Agent 组织／跨任务流程，不修改其他产品、全局配置或插件缓存，不退出、重启、重装或前台唤起 Codex／ChatGPT。
