# Future Clinic

Future Clinic 是可独立安装的研究会诊 Skill：开放发现有实质差别的做法，研究到足以比较和筛选；诊断、核验、更新与方案选择查清决定当前答案的关键证据。涉及既有项目时恢复相关历史、最新有效决定与真实资源，用历史结果和证据约束推荐。

把产物或行业名还原成需要完成的作用，沿不同功能寻找跨领域方法，比较具体机制、输入和迁移条件。需要突破常规办法时，用挑战目标追查必须改变的方法与前提；按判断需要实际使用原始资料、专业工具、假设检验及外部反馈。它们是按需组合的方法，不是每题新增固定阶段，也不以专业角色、篇幅或更强承诺代替分析。

在明显扩大搜索、缩小候选或投入更多深度前，用当前的探索构想、初搜后候选及依据、或待证主张接受临时独立质疑。质疑者取得原话、相关原始背景、有效约束与完整待审对象；主 Agent 据返回回读、检索、核实现或计算，实际修订入口、候选或主张，再把实质修订稿与依据交回审视。取证与质疑交替，不先纯讨论固定几轮，也不靠自评或模型共识证明结论。独立能力受限时明确限制与实际轻量替代；简单题和普通补读保持轻量。

只有真实用户才能决定的目标或取舍，保留直接提问入口；复用已答事项，不能由 Agent 模拟用户。等待只限制依赖部分，回答后在同一会诊内继续。

候选关系支撑比较，区分替代、互补组件、共同能力与条件分支。开放研究不强制选唯一赢家；需要选择时匹配证据强度，公平解释最强替代。完整未来推演按原题需要启用，说明行动、反馈、后续选择、失败与换路；关键可查疑点本轮查清，不影响当前判断的完整深研可后续承接。

报告直接回答原题，具体细节在适当位置完整展开一次。已有候选的验证责任、决定性反例与事实边界不能为了简洁而删除。不固定阶段数、方向数或 Agent 人数；图是可选辅助，简单与指定任务直接完成。

## 使用

下载本仓库，或克隆为名为 `future-clinic` 的文件夹：

```sh
git clone https://github.com/Ginsaka-You/future-clinic-skill.git future-clinic
```

将这个文件夹放到所用宿主支持的 Skill 目录，按宿主方式加载。入口为根目录的 `SKILL.md`；`agents/openai.yaml` 包含 Codex 的显示信息与显式调用设置。这里提供的是 Skill 仓库，不是已经上架的 ChatGPT 插件，跨宿主的发现、调用和工具权限需分别验证。

在支持相应语法的宿主中显式调用：

```text
$future-clinic 我们已考虑预读讨论、现场共读和两者组合。
请判断怎样验证这些办法，比较整体推进路线，推荐当前做法，
并深入推演第一项反馈、后续发展和何时应改走其他路线。
```

可以先用 [Future Brief](https://github.com/Ginsaka-You/future-brief-skill) 整理目标与事实，但它不是运行 Clinic 的前提，也不会自动调用 Clinic。

## 交付与运行条件

- 一份完整 Markdown、一份同源同主名 PDF、聊天摘要。
- 研究需要宿主提供适当的文件与联网能力；本仓库不提供模型或搜索服务。
- PDF 渲染脚本、样式和中文字体内置，不依赖其他 Skill。
- PDF 运行环境与命令见 [渲染说明](references/pdf-rendering.md)，依赖版本见 `requirements.txt`。需要安装时优先使用隔离环境。
- 默认署名为 `游诗辰 · Future Clinic`。示例和代码不包含个人业务报告或会话记录。

## 边界

会诊默认研究与设计，不授权采购、发送消息、部署或改动业务系统。预测保留条件与未知，不保证未来结果；不能把静态测试通过当成研究质量或现实效果证明。

2026-10-20 本轮按用户要求未运行测试、行为演练、正常入口调用或 PDF 渲染，只做内容审阅及安装／发布写入回读；效果由人工验证。维护者获准进行相应检查时可运行：

```sh
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py'
```

Python 命令须使用已具备 `requirements.txt` 中依赖的环境。包与渲染测试只检查相应功能；实际报告的核验原则见 [行为验证说明](tests/behavioral-acceptance.md)。

[候选关系与主路线示例](examples/候选关系与主路线示例.md)是虚构的组织及排版样例，不是实际会诊或效果证明。公开仓库不包含用户业务材料、会话记录或私有评测数据；局部试用也不证明跨模型、跨宿主或长期效果。
